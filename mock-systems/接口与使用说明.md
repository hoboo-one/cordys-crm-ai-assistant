# CRM 模拟业务系统接入包

本包包含三个独立只读 HTTP 服务。解压到同一个文件夹，启动 Docker Desktop，再双击 `start.cmd`。首次启动需要下载 Python 运行镜像。每个系统的原始数据在 `data/*.json`，同名 CSV 可用 Excel 查阅。运行时读取 JSON；修改后执行 `docker compose restart` 重新载入。需要停止时执行 `docker compose stop`。

从 Git 克隆后，先在项目根目录复制 `.env.example` 为 `.env`，填入本机的 DeepSeek 密钥文件、HTTPS 证书和私钥路径。把 `crm-connections.example.json` 复制为 `crm-connections.json`。为订单、仓库、物流分别生成测试 Token，填入对应的 `token` 字段，并将同一个值分别写入 `tokens/orders.txt`、`tokens/warehouse.txt`、`tokens/logistics.txt`。在项目根目录启动 CRM Compose，再启动模拟服务，使模拟服务接入 CRM 的 Docker 网络。

## 地址与凭证

打开 `crm-connections.json` 即可取得每个系统的本机地址、CRM 容器网络地址和专属测试 Token。三个服务分别只读取 `tokens/` 下自己的凭证。将配置交给调用方后端保管。每次查询都在 HTTP 请求头里传 `Authorization: Bearer 对应系统的Token`。

| 系统 | Windows 本机 GET 接口 | 参数 | 结果 |
|---|---|---|---|
| 订单 | http://127.0.0.1:18101/api/orders | order_id | 订单号、客户编号、业务状态、创建时间 |
| 仓库 | http://127.0.0.1:18102/api/shipments | order_id | 本单全部包裹，含发货记录号、包裹序号、承运商、运单号、备注和更新时间 |
| 物流 | http://127.0.0.1:18103/api/tracking | carrier、tracking_no | 按时间先后排列的承运商事件，含记录号、事件码、说明和时间 |

响应为 JSON，成功时含 `system`、`count` 和 `items`。缺少或错用凭证返回 401；缺必填参数返回 400；订单不存在返回 404。仓库或物流查询成功但无匹配数据时返回 200 和空数组。三个端口各有不含业务数据的 `/health`。宿主机端口只绑定本机。

## 用 PowerShell 查一笔单

在解压目录打开 PowerShell，复制以下代码。它从配置读凭证，按实际返回的包裹查每个运单。

```powershell
$cfg = Get-Content -Raw ./crm-connections.json | ConvertFrom-Json
function Query-System($service, $query) {
    Invoke-RestMethod -Uri ($service.local_url + '?' + $query) -Headers @{Authorization = 'Bearer ' + $service.token}
}
$order = Query-System $cfg.orders 'order_id=O-103'
$order.items
$warehouse = Query-System $cfg.warehouse ('order_id=' + $order.items[0].order_id)
foreach ($parcel in $warehouse.items) {
    $tracking = Query-System $cfg.logistics ('carrier=' + $parcel.carrier + '&tracking_no=' + $parcel.tracking_no)
    $tracking.items | Format-Table
}
```

## 演示样例

| 订单 | 包裹 | 预期结果 |
|---|---:|---|
| O-136 | 0 | 订单存在，仓库暂无运单 |
| O-102 | 1 | 订单已标记发货，仓库备注换箱，物流只有电子面单，实际交接待确认 |
| O-103 | 2 | 一单多包裹，仅 1 个包裹有揽收记录 |
| O-104 | 2 | 两个包裹均有揽收记录 |

只用承运商返回的 `PICKED_UP` 事件确认揽收；`LABEL_CREATED` 表示建单。时间均带中国标准时间偏移量。模拟客户编号为 C001 至 C010，尚未绑定 Cordys 里的真实客户记录。

## 后续从 Cordys 接入

启动脚本发现现有网络 `cordys-local_default` 时，会加用 `compose.crm.yaml`。此时 Cordys 后端用配置里的 `crm_container_url` 访问三个服务。容器里的 127.0.0.1 指容器自己。换到其他机器部署时，可修改此文件中的外部网络名，并用两个 Compose 文件启动。

业务接口只校验应用凭证。下一阶段由 CRM 后端识别当前销售、校验订单所属客户的数据权限，再查询相应包裹和物流。AI 使用获准展示的结果。

## 复测

运行 `python verify.py`（Python 3）。脚本逐笔对照 40 笔订单、50 个包裹、80 条物流事件，并检查缺失、错误和跨系统凭证，以及未知订单、空结果和参数错误。配置文件内为本地练习专用凭证。
